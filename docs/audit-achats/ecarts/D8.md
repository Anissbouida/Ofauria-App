### G-D8-01 — Le grand livre dépend d'un flag OFF en production et d'un SAVEPOINT qui avale les échecs

- **Preuve** :

  - Base : `SELECT count(*), SUM(total_amount) FROM invoices i WHERE invoice_type='received' AND status<>'cancelled' AND NOT EXISTS (SELECT 1 FROM journal_entries je WHERE je.source_id=i.id AND je.status<>'reversed')` → **25 | 20 086,91** ; paiements sans écriture : invoice 23 (12 121,38), expense 12 (7 575), advance 4 (1 500), salary 1 (2 800), income 1 (12 538,74) ; répartition `source_kind` : backfill 994, invoice 14, payment 46 → **94 % des écritures viennent du bouton « Générer »**.

- **Manque vs standard ERP** : dans NetSuite/Odoo/SAP, la pièce *est* comptabilisée ou n'existe pas (transaction unique). Ici la comptabilisation est (1) optionnelle, (2) silencieusement abandonnée, (3) rattrapée par un backfill manuel qui ne couvre pas tout (`ledger-backfill.service.ts:38-196` : factures, paiements, ventes, saisies manuelles ; pas avances, pertes, écarts, dotations, RAS).

- **Priorité** : **P0** (contrôle financier).
- **Cible** :
  - *Règle* : la génération est **toujours active** et **synchrone** pour les événements financiers (facture, avoir, paiement, encaissement, réception → GR/IR, retenue, dotation, RAS). Un échec du générateur fait échouer la transaction métier (pas de SAVEPOINT), comme un `WHEN-VALIDATE-RECORD` qui lève `FORM_TRIGGER_FAILURE`. Seuls les événements « non financiers » (vente POS déjà couverte par la saisie manuelle, pertes tant que G-D8-12 n'est pas livré) restent asynchrones.
  - *Transition contrôlée* : `module_parameters('ledger','posting_mode') ∈ (strict, outbox)`. En mode `outbox` (phase de migration, 2-4 semaines) : table
    ```sql
    CREATE TABLE ledger_outbox (
      id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
      source_kind varchar(30) NOT NULL, source_id uuid NOT NULL, source_detail varchar(40),
      status varchar(10) NOT NULL DEFAULT 'pending' CHECK (status IN ('pending','posted','failed')),
      attempts int NOT NULL DEFAULT 0, last_error text, payload jsonb,
      created_at timestamptz DEFAULT now(), posted_at timestamptz,
      UNIQUE (source_kind, source_id, COALESCE(source_detail,''))
    ```

    alimentée par le code à la place du SAVEPOINT ; job `POST /ledger/outbox/replay` (admin) + bandeau `StatusBanner` « N pièces non comptabilisées » dans `EcrituresTab`. En mode `strict`, la table ne sert qu'à l'audit des échecs.
  - *Suppression du flag* : retirer `LEDGER_AUTOGEN`, `LEDGER_BACKED_DEBTS`, `LEDGER_SHADOW_MODE` (jamais lus, `feature-flags.ts:36-39`) ; `FLAGS.LEDGER_AUTOGEN` remplacé par une constante `true` puis les 27 `if` supprimés.
  - *Endpoints* : `GET /ledger/outbox?status=` ; `POST /ledger/outbox/:id/replay` ; `GET /ledger/health` (= `v_reconciliation_check` + outbox + G-D8-17).
  - *Tests* : suite vitest `journal-generator.test.ts` (facture avec/sans TVA ligne, paiement cash/chèque/traite/avoir, réception GR/IR, idempotence, période close) sur une base de test (`DATABASE_URL_TEST`), 2 scénarios e2e migrés de `test-ledger-e2e.ts`.
- **Reprise** : (1) lot 0 immédiat sans code : ajouter `LEDGER_AUTOGEN=on` à `deploy.yml:208` et relancer « Générer » (backfill) → rattrape 25 factures + 41 paiements (après G-D8-03 pour les avances) ; (2) une fois en `strict`, `runFullBackfill` devient un outil de contrôle (dry-run) et non d'alimentation.
- **Effort** : M (flag + outbox + tests) ; lot 0 : S.
- **Dépendances** : G-D8-03 (CHECK) avant tout backfill ; G-D8-16 (périodes 2027) avant le 01/01/2027.
- **Risques** : en mode `strict`, une anomalie de paramétrage (catégorie sans compte, auxiliaire manquant) bloque la saisie métier → d'où la table de paramétrage testable (G-D8-09) et le mode `outbox` transitoire.

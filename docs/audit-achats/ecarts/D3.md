## 2. Fiches d'écart

Conventions des fiches : DDL esquissé (noms indicatifs), `document_type` = clé polymorphe texte (`purchase_request`, `purchase_order`, `supplier_invoice`, `expense_payment`), l'application se connecte avec **un seul rôle PG** (`DATABASE_URL`) donc l'immuabilité se fait par **trigger de refus**, pas par `REVOKE`. Analogie Oracle rappelée quand elle aide : trigger `BEFORE UPDATE` côté base = `WHEN-VALIDATE-RECORD` infranchissable par l'API ; `SET LOCAL app.user_id` = `DBMS_SESSION.SET_CONTEXT`.

Socle commun (mig 304, préalable à toutes les fiches) : `document_actions` (G-D3-03), `reason_codes` via `ref_entries` (G-D3-08), `SET LOCAL app.user_id` posé par un helper `withActor(client, userId)` utilisé par tous les repositories achats. Les trois fiches P0 forment le **lot 1** livrable seul.

- **Impact métier** : une erreur d'unité (sac vs kg, Languette 0,16 ↔ 16) ou un prix aberrant (Mangue 0,04 DH/kg) passe sans alerte et recalcule tous les coûts de recettes (`syncProductPrice`) ; aucune négociation n'est déclenchée par une hausse.
- **Priorité** : P1.
- **Conception cible** :
  - Fonction (mig 312) `fn_reference_price(p_kind text, p_item uuid, p_supplier uuid) RETURNS numeric` : priorité `supplier_item_prices` (D1, quand elle existe) → dernier `ingredient_lots.unit_cost` du même fournisseur → dernier lot toutes sources → `ingredients.unit_cost` ; `purchase_order_items.reference_price numeric(12,4)` et `price_deviation_pct numeric(7,2)` **snapshot** à la création/modification de la ligne (trigger `BEFORE INSERT OR UPDATE OF unit_price`).
  - Paramètres `module_parameters` : `purchasing.price_warn_pct` (défaut 5), `purchasing.price_approval_pct` (défaut 20) ; G-D3-01 lit `MAX(price_deviation_pct)` du BC comme condition `price_deviation_pct`.
  - Endpoint : `GET /purchasing/reference-price?kind=&id=&supplier=` pour l'UI ; `POST /purchase-orders` renvoie `warnings[]` (ligne, référence, écart) sans bloquer sous `price_approval_pct`.
  - Écran : dans `CreatePOModal`/`GeneratePOModal`, cellule prix avec pastille « +23 % vs 12,50 DH (dernier prix OVOTEC) » (`odoo-tag` warning) et `StatusBanner tone="warning"` « 2 lignes hors tarif : le BC sera soumis à approbation » ; unité affichée = unité saisie (prix par contenant quand la ligne est en contenants).
- **Reprise des données** : `reference_price`/`price_deviation_pct` NULL pour l'existant ; rapport des 15 lignes > 20 % pour vérification des unités (W-35).
- **Effort** : S (M avec `supplier_item_prices`).
- **Dépendances** : G-D3-01 (condition) ; D1 C-D1-03 (prix de référence qualifié) ; D4 C-D4-03 (prix par contenant vs par base : comparer dans la même unité, sinon faux positifs).
- **Risques** : faux positifs massifs tant que l'unité d'achat n'est pas figée (22 articles à variation > 100 % par changement d'unité) → ne comparer que des lignes de même `qty_per_container` ou en prix/base.
